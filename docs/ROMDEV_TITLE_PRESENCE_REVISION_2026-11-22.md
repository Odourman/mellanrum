# ROM DEVELOPMENT: MAIN title + Presence change order (Issue #8)

**Authority:** `docs/MAIN_TO_ROMDEV_TITLE_AND_PRESENCE_2026-11-22.md` on `main`; limited to two approved visual revisions. This handoff documents implementation and developer tests, not MAIN art acceptance, Pachinko 2.0 or independent Verification. PR remains Draft/unmerged. No changes to 15 original `reference/rooms.json` rooms or V5.1 physics.

## A: Title only MELLANRUM

- Exact horizontal word `MELLANRUM` in a 9-character, 3×5 bespoke block font, two-pixel margins in the **full 40-bit TIA playfield**; 40-bit rows generated deterministically by `scripts/generate_rom_data.py`, two halves output within each scanline using late PF register rewrites. `CTRLPF=0` only for title, restored to mirrored `CTRLPF=1` during gameplay.
- Removed all old `TitleMEL/LAN/RUM/KAM/FRI` tables. No other rendered text is present in the title renderer. Menu remains same two modes and original console controls (SELECT toggles / FIRE starts).
- Two abstract non-text forms beneath title: left green conifer-like triangle = KAMPANJ; right open branch shape = FRI SKOG. Bright versus dim indicates selection. Their design requires learning; they are distinguishable by position and luminance but not written labels.
- Video scanline accounting in local full 6502 CPU/RIOT/WSYNC model: title 262 NTSC lines. The title raster's explicit 32/56/23/24/55 WSYNC holds plus two blank boundary wraps fit the 192-line visible interval. The full word is unchanged by menu selection. Both icon halves switch PF color after the left PF2 pixels finish (~cycle 50), before right PF2 pixels start (~cycle 66). Real Stella screenshots are an additional separately identified layer of evidence.

## B: Presence as render-only between-tree negative space

- `SetShadowVisibility` runs once in VBlank. Uses **existing authoritative V5.1** `presence` states: 1 warning and 2 active; 0 normal / 3 release produce no silhouette. A deterministic `soundStep & 63 < 24` visual gate produces a 24-frame glimpse / 40-frame absence (~0.4 s visible, ~0.67 s absent at NTSC 60 Hz), not random flashes.
- `ShadowCrownOr/And` and `ShadowStemOr/And` tables shape a visually temporary central forest interruption between reflected pines, with a narrowed void with disconnected edges, while central PF2 bits that resembled paired eyes in the first real Stella capture have been removed. No anatomical face or eyes are intended. WARNING shows fragments of crown only; ACTIVE also carves lower band fragments. TIA uses existing `PF2` register; P0 owl, P1 cursor, BL stone and M0 exit are untouched.
- New `shadowOn` at zero page follows ONLY `presence` and `soundStep`; it does not enter `PassableCandidate`, `mapRows`, `pfbuf`, the echo queue, phase, stone logic, exit or any collision rule. `CrownLast3` precomputes BL/M0 enable scratch to keep stem/PF write in the existing scanline. No extra sprite, hitbox or AI.
- Does not add strobing or jumpscare. Warning, active and release still separately encoded in `PresenceHUD` and sound.
- Any judgment of how *recognizable/ambiguous* the shadow looks is **artistic review**, not CI success.

## Testing boundaries and reproducibility

1. Original `reference/rooms.json` and GRAPHICS V5.1 source geometry remain byte-identical; original packages are separately hashed and CRC-validated in previous `docs/PROVENANCE.md`.
2. `python scripts/generate_rom_data.py --original reference/rooms.json --graphics graphics --output rom/src/data.inc --check` ensures generated bytes match originals.
3. `python scripts/check_title_presence.py` exercises actual 6507 code for title SELECT and physical `PF2` writes during real V5.1 warning/active/release states for III-03, III-04, III-05 and checks the entire 48-byte playfield buffer and collision map unchanged after rendering.
4. `python scripts/check_frame_budget.py`, `python scripts/check_input.py`, `python scripts/check_rom_vs_model.py`, `python scripts/check_playfield.py`, reference unit tests: developer CPU + model, not a hardware emulator.
5. Real DASM and native byte comparison in GitHub Actions `game.yml` and core CI. Separate `title-presence-stella.yml` builds the uninstrumented ROM and captures actual Stella PNG. To observe precise Presence windows, `scripts/make_visual_evidence_rom.py` creates **explicitly instrumented Reset-only test variants**, one per original room/beat; **these variant hashes differ from production ROM**. The unchanged game rendering path is exercised in the real emulator. This is NOT frame-exact campaign replay and is not independent verification.
6. Recheck 262-line actual emulator raster timing, collision overlays and all frame-indexed user replay in Pachinko 2.0 / independent Verification, as specifically required by MAIN; never transfer the baseline old ROM hash's PASS to the revised ROM.
